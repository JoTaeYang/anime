# Phase 1 설계 — 실제 캐릭터 리깅 (assets/character.blend)

> 작성일: 2026-07-18 · 상태: 승인됨 (사용자, 설계 위임)
> 상위 문서: [PLAN.md](../../../PLAN.md) Phase 1 · 선행: [Phase 0 설계](2026-07-17-phase0-pipeline-design.md)

## 0. 대상 캐릭터 (실측)

`assets/character.blend` — Meshy AI 생성 애니메 스타일 모험가 소녀 (짐승 후드).
- 메시 1개("Mesh_0"), 276,737 정점 / 553,716 폴리곤 (전부 삼각형, N-gon 0)
- 리깅 없음(버텍스 그룹 0), 모디파이어·셰이프키 없음, 트랜스폼 깨끗(loc 0 / rot 0 / scale 1)
- 키 1.899m (Z-up), 정면 −Y (파이프라인 관례와 일치), T포즈
- 재질 1개, 2048² 팩 텍스처 4장, UV 1개
- 부속물: 꼬리(대형), 치마+깃털 장식, 목도리 자락, 후드(귀 포함), 파우치(자연 비대칭 요소)
- 데포르메 비율(큰 머리) — 기본 메타리그 단순 스케일로는 관절이 맞지 않음

## 1. 확정된 전제 (사용자 결정)

| 항목 | 결정 |
|---|---|
| 품질 목표 | **애니메이션 관점에서 실제 주인공급.** 웨이트 품질을 사용자 승인 게이트까지 끌어올린다 |
| 메시 최적화 | **범위 밖** (별도 담당자). 55만 삼각형 그대로 작업 |
| 최적화 메시 수령 방식 | 경량 메시가 돌아오면 **파이프라인 재실행**으로 재리깅 (모든 절차·좌표가 스크립트/데이터로 남아야 하는 이유) |
| 부속물 | **전부 본 체인** (꼬리·치마·목도리·후드 귀). 흔들림 구동(수제 vs Unity 물리)은 Phase 2 결정 |
| 승인 루프 | 반복 중: 턴테이블 MP4 + 고해상도 스틸. **최종 승인: Unity 에디터에서 사용자 직접** (Phase 0 미룬 눈검증 겸용) |
| 메타리그 맞춤 | **스크립트 자동 추정 + 에이전트 렌더 루프 보정** (좌표는 프로필 데이터 파일로 영속). 자동 추정 불가 부위만 MCP/확대 렌더로 보완 |

## 2. 캐릭터 프로필 시스템

파이프라인의 하드코딩("Dummy", 더미 좌표, dummy.fbx)을 프로필로 일반화한다.

- `scripts/lib/profiles/dummy.py` / `scripts/lib/profiles/character.py`
- 프로필 내용: 입력 소스(절차 생성 vs .blend 경로), 메시 오브젝트명, 관절 좌표 테이블, 실측 힙 높이·허용오차, 부속물 본 정의, 마커 단언 사용 여부
- `run.ps1 -Profile <name>` (기본값 character). 스테이지·체크 스크립트는 프로필을 통해서만 이름/좌표에 접근
- **더미 프로필은 파이프라인 자가 테스트로 영구 보존** — 캐릭터 작업 중 파이프라인 자체 회귀를 5분 내 판별
- 좌우 감시(laterality centroid) 단언은 **더미 전용** (캐릭터는 파우치 등 자연 비대칭). `faces_plus_z`(손 x좌표 비교)는 양쪽 공통

## 3. 스테이지 구성

| 스테이지 | Phase 1에서 | 내용 |
|---|---|---|
| `00_intake` | **신규 (00_mesh 대체, 캐릭터 프로필 시)** | assets 로드 → 사전 점검(트랜스폼·단위·정면 −Y·대칭축) → 키 1.9m 유지, 힙 높이 실측 → `build/00_mesh.blend` |
| `01_rig` | **확장** | 프로필 좌표로 메타리그 본 배치 + 부속물 체인 추가 → rigify 생성 → 자동 웨이트 → 부위별 보정 스크립트 |
| `02_anim` | 재사용 | 호흡 운반체 (실사용 애니는 Phase 2) |
| `03_bake` | 재사용 | bone_map에 부속물 이름 추가만 |
| `04_export` | 재사용 | 산출물명 프로필화 (character.fbx) + `exports/character_meta.json` 기록 |

## 4. 부속물 본 설계

Rigify 샘플 체인을 메타리그에 추가 (`spines.basic_tail` / `basic.copy_chain`):
- 꼬리: 1체인 × 5본 (뿌리→끝)
- 치마: 8체인 × 2본 (앞2·뒤2·좌2·우2 — 실제 깃털 장식 분포 보고 조정 가능)
- 목도리 자락: 2체인 × 2본
- 후드 귀: 좌우 각 1본

Unity 이름: `Tail1..5`, `SkirtF1a/b` 형식으로 bone_map에 추가. 전부 Humanoid 미매핑 여분 본 (Phase 0 트위스트 본으로 검증된 경로). Unity 단언에 부속물 본 존재 확인 추가.

## 5. 메타리그 맞춤 루프

1. `scripts/tools/estimate_landmarks.py`: 메시 분석(높이별 단면, 대칭축, 사지 클러스터)으로 관절 좌표 초안 → `profiles/character.py`에 기록
2. `01_rig`가 좌표대로 메타리그 배치 (Phase 0의 P-테이블 배치 코드 일반화)
3. **메타리그 오버레이 렌더** (본 와이어를 메시 위에 겹쳐 그림) + 컨택트 시트를 에이전트가 읽고 어긋난 관절을 좌표 파일에서 수정 → 재실행 (수렴까지)
4. 손가락 등 자동 추정 불가 부위: 확대 렌더 반복, 필요시 MCP 인터랙티브 → 확정 좌표는 반드시 프로필로 환원

## 6. 웨이트 품질 루프

자동 웨이트 → 극단 포즈 렌더로 문제 부위 발견 → 부위별 보정 스크립트(치마↔다리 영향 분리, 꼬리 뿌리 스무딩, 겨드랑이 클램프 등 — 렌더가 알려주는 대로) → 재렌더 수렴. 보정도 전부 스크립트로 영속.

극단 포즈 세트 확장: 기존(팔 들기·쪼그리기·비틀기) + **꼬리 들기 · 다리 벌리기(치마 검사)**.

## 7. 검증 3층

- **기계**: Unity 단언 재사용 + 일반화 — 힙 높이 기대치는 `exports/character_meta.json`에서 읽음(하드코딩 제거). 부속물 본 존재 단언 추가. 더미 프로필 회귀(기존 9/9) 유지.
- **에이전트**: 컨택트 시트(확장 포즈) + 메타리그 오버레이 렌더.
- **사용자**: `scripts/preview/user_preview.py` — 1080p 턴테이블 MP4(레스트+idle) + 극단 포즈 고해상도 스틸 → `previews/user/`. 반복 승인용. 최종 승인은 Unity 에디터.

## 8. 완료 기준

1. `run.ps1 all -Profile character` 클린 통과, Unity 단언 전부 초록
2. 극단 포즈 5종에서 메시 파손 없음 (에이전트 시트 검사 통과)
3. **사용자가 턴테이블/스틸을 보고 웨이트 품질 승인**
4. 사용자가 Unity 에디터에서 최종 확인 (Phase 0 눈검증 겸)
5. 더미 프로필 회귀 통과 유지

## 9. 하지 않는 것 (YAGNI)

메시 최적화(타인 담당) · Unity 물리(스프링 본) 셋업(Phase 2) · 표정/셰이프키 · Mixamo 리타게팅(Phase 2a) · 실사용 애니메이션 제작(Phase 2b) · 텍스처/재질 가공.

## 10. 리스크

| 리스크 | 완화 |

| 자동 랜드마크 추정이 데포르메 체형에서 부정확 | 오버레이 렌더 루프로 보정, 좌표는 데이터 파일이라 수정이 싸다 |

| Rigify 체인 샘플의 5.1 API 차이 | Phase 0 방식대로 사전 프로브 후 계획에 실측 반영 |
