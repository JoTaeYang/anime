## 0. 배경 — walk 파일럿 판정과 방향 전환

walk 파일럿(2b 수제)은 **불만족 판정** (2026-07-20, 사용자 + 에이전트 재확인). 교정 3회 후에도:
- 발 구름(뒤꿈치→앞꿈치 롤) 부재 — foot_ik 위치만 키잉, 발 회전 미사용
- 접지/통과 포즈가 화면에서 안 읽힘 (소극적 스트라이드, 치마에 가린 무릎)
- 상체 무게 이동 부재 (출렁임 제거가 정지 인형화로 귀결)
- 사인 대칭 타이밍의 구조적 무게감 한계

결론: 이동 계열을 수제 절차 생성으로 주인공급까지 끌어올리는 것은 비효율.
**타이밍·무게는 모캡에서, 개성은 그 위의 편집에서** 가져오는 하이브리드로 전환한다.
파일럿의 산출물(액션 디스패처, 포즈 데이터 패턴, 비교 루프, 팔로우스루, 검증 3층)은
폐기가 아니라 **편집·시그니처 제작 루프로 용도 확정**.

## 1. 확정 결정 (사용자)

| 항목 | 결정 |
|---|---|
| 방향 | C안: 단계 하이브리드 — Mixamo 베이스 우선, 파생 제작은 그 위에 |

| 무기 | 검 모델 아직 없음 → Unity 손 본 소켓 부착 전제, 애니메이션은 그립 손 모양만 준비 |

## 2. 3단 구조

### 2a-1. Unity 휴머노이드 직접 리타게팅 (즉시)
- Mixamo 클립 FBX를 Unity에 **Humanoid로 임포트** → Phase 1 아바타(명시 매핑)에 자동 리타게팅.
- Blender 작업 없음. 이동 + 기본 전투 전체 커버.
- Humanoid 리타게팅이 이 프로젝트가 Humanoid 규격을 택한 이유의 실현이다.

### 2a-2. Blender 최소 리타게팅 (편집이 실제로 필요할 때만)
- mixamorig:* 본 → 우리 리그 본 매핑 + 레스트 포즈 보정 → 액션으로 반입.
- 편집 후 기존 bake→export→Unity 경로로 재진입 (액션명/클립 길이 일반화는 T6에서 완료).
- **선제작 금지 (YAGNI)**: 첫 편집 수요가 확정되기 전에는 만들지 않는다.

### 2b 개편. 시그니처 액션 (돌진 베기 등)
- 라이브러리에 없는 동작은 가장 가까운 Mixamo 클립(예: Running Slash 계열)을 2a-2로
  가져와 베이스로 편집한다. AI 생성 레퍼런스 시트 → 모캡 베이스로 교체되므로
  타이밍 문제가 원천 해결된다.
- 기존 비교 루프(렌더 → 에이전트 판독 → 데이터 교정)가 "베이스 대 편집본" 검증 눈.
- 공격은 포즈-투-포즈 + 강한 실루엣이라 걷기보다 수제/편집에 유리한 영역.

## 3. 사용자 할 일 (2a-1 착수 조건)

Adobe 계정으로 Mixamo에서 다운로드 → `assets/mocap/`에 배치.
- 포맷: **FBX Binary, Without Skin, 30fps** (구현 계획에서 클립별 정확한 이름·옵션 확정)
- 대략 목록: Idle, Walking, Running, Stand To Roll(구르기), 검 베기 3종(콤보),
  Sword And Shield Impact(피격), Sword And Shield Death(사망),
  Running Slash 계열(돌진 베기 베이스 후보).

## 4. Unity 측 구성 (2a-1)

- `unity/AvatarCheck`에 클립 임포트 자동화 에디터 스크립트: Humanoid 설정, 루프 플래그,
  아바타 연결, 임포트 클린 단언 (기존 report.json 체계 확장).
- 간단한 Animator Controller: 이동 블렌드트리(idle/walk/run) + 트리거(공격/피격/사망/구르기).
- **실기동 확인 씬**: 사용자가 에디터에서 주인공을 직접 움직여 보는 것이 승인 게이트.

## 5. 검증 3층

- **기계**: 클립별 임포트 클린 + Humanoid 유효 + 길이/루프 단언. 단언 약화·화이트리스트 금지
  (빈 포인터 조건부 규칙 등 기존 승인 규칙 유지).
- **에이전트**: 2a-2/2b 편집 클립은 기존 비교 루프로 수렴 판정.
- **사용자**: Unity 실기동 확인 = "품질 탈출" 판정 지점. 시그니처는 액션별 프리뷰 승인.

## 6. 하지 않는 것 (YAGNI)

- 전 클립 Blender 리타게팅 (편집 필요 클립만)
- NLA 멀티 액션 관리 (Mixamo 클립은 Unity 자산으로 관리)
- 무기 모델 반입·본 추가 (소켓 방식 전제)
- 스프링 본(부속물 인게임 2차 모션) — 별도 후속 브랜치
- Mixamo 자동 다운로드 (Adobe 로그인 필요 — 사용자 수동)

## 7. 완료 기준

1. 사용자가 받은 Mixamo 클립 전부가 Unity에서 임포트 클린 + 아바타 연결 (기계 단언 초록)
2. 실기동 씬에서 이동 블렌드 + 공격/피격/사망/구르기 재생 확인 (사용자 게이트)
3. 돌진 베기 1종을 모캡 베이스 편집으로 제작·승인 (2a-2 + 2b 개편 루프의 실증)
4. dummy 프로필 회귀 유지
5. PLAN.md Phase 2 갱신 (하이브리드 확정 반영)
