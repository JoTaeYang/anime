# Phase 2 파일럿 설계 — 레퍼런스 기반 walk 사이클

> 작성일: 2026-07-19 · 상태: 승인됨 (사용자)
> 상위 문서: [PLAN.md](../../../PLAN.md) Phase 2 · 선행: [Phase 1 설계](2026-07-18-phase1-character-rigging-design.md)

## 0. 배경과 판정 목적

사용자가 walk 레퍼런스 시트(`refs/walk/walk_side_8frames.png` — AI 생성, 8키, 측면, 캐릭터 본인)를 제공했다. PLAN은 이동 계열을 Mixamo(2a)에 배정했으나, 사용자 결정(C안)으로 **walk를 2b(레퍼런스 수제) 파일럿**으로 먼저 만든다. 파일럿의 존재 이유는 "레퍼런스 수제가 주인공급 품질이 되는가"의 실증이며, 그 결과가 Phase 2 전체의 방향을 가른다:

- 파일럿 성공 → 전부 레퍼런스 수제(Mixamo 폐기) 검토
- 파일럿 불만족 → walk만 Mixamo로 교체, PLAN 원안(하이브리드) 복귀

어느 쪽이든 이 파일럿이 구축하는 2b 루프(포즈 데이터 → 적용 → 비교 렌더 → 교정)는 개성 액션에 필수라 버려지는 작업이 없다.

## 1. 확정 결정 (사용자)

| 항목 | 결정 |
|---|---|
| 파일럿 대상 | walk 1개 (레퍼런스: 8키 측면 시트) |
| 파일럿 범위 | 몸체 포즈 + **부속물 절차 팔로스루** (수제 부속물 키는 아님) |
| 포즈 추출 방식 | **에이전트 판독 + 포즈 데이터 루프** (CV 자동 추출·Mixamo 베이스 기각) |
| AI 레퍼런스 취급 | PLAN §5 그대로 — 포즈만 참고, 비율은 3D 모델 기준 고정 |

## 2. 액션 시스템 구조 (02_anim의 진화)

- `02_anim`은 **액션 빌더 디스패처**가 된다: 프로필의 `ANIM_ACTION` 값이 빌더를 지정.
  - dummy: 기존 호흡 운반체 유지 (회귀 불변)
  - character: `walk` → `scripts/anim/walk_build.py`
- 포즈 수치는 코드와 분리된 데이터 파일 `scripts/anim/walk_poses.py` (키프레임 → 컨트롤 본 → 회전/위치). Phase 1 랜드마크와 같은 패턴 — 교정 루프의 수정 대상이 곧 이 파일.
- `scripts/anim/` 디렉터리 신설 (PLAN §3 저장소 구조에 이미 예정된 위치).

## 3. 포즈 적용 방식

- **24fps, 24프레임 사이클, 제자리 걷기** (루트 이동은 엔진 몫). 레퍼런스 8키를 3프레임 간격 배치, f25 = f1 (루프 폐쇄).
- **다리는 IK**: `foot_ik` 컨트롤 위치 키잉으로 접지를 구조적으로 보장. 접지 중 발은 등속 후진 (제자리 걷기 표준). FK 다리 기각 사유: 발 미끄러짐·지면 뚫림이 필연.
- 상체(척추 숙임, 팔 스윙, 골반 요잉·상하동)는 FK 컨트롤 회전 키.
- Rigify 컨트롤 본의 정확한 이름(foot_ik.L 등)과 IK/FK 스위치 상태는 **구현 계획 작성 시 실측 프로브로 확정** (Phase 0/1 방식).

## 4. 부속물 팔로스루 (절차 규칙)

몸체 키 완성 후 후처리 패스가 부속물 컨트롤(꼬리 5, 치마 16, 목도리 4, 후드 귀 2)에 키를 자동 생성:

- 규칙: **부모 회전 변화의 지연(2~4프레임) + 감쇠(0.5~0.7) 복사**, 체인 하위로 갈수록 지연 누적.
- 파라미터(지연·감쇠·축)는 데이터로 노출 — 교정 루프에서 조정 가능.
- Unity 스프링 본 물리로의 대체 여부는 파일럿 밖 (본이 있으므로 언제든 전환 가능).

## 5. 비교 시트 (교정 루프의 눈)

`scripts/preview/walk_compare.py`:
- 레퍼런스 시트를 8칸으로 분할 (분할 좌표는 구현 시 이미지 실측)
- 우리 리그를 같은 측면 앵글, 8개 키 시점에 렌더
- **상단 = 레퍼런스 / 하단 = 우리 렌더**의 2×8 그리드 PNG 한 장 합성
- 에이전트가 읽고 어긋난 관절을 `walk_poses.py`에서 수정 → 재실행 (수렴까지)

## 6. 검증 3층

- **기계**:
  - Walk 액션 존재, 프레임 1–24, 루프 폐쇄 (f1 ≈ f25 포즈)
  - **발 미끄러짐 검사**: 접지 구간에서 발 world 속도 일정성 + 접지 높이 z≈0
  - 베이크→FBX→Unity 통과. Unity 클립 단언은 meta.json에 클립 이름·기대 길이(1.0s)를 실어 일반화 (현행 idle 1.5~2.5s 하드코딩 제거)
- **에이전트**: 비교 시트 수렴(8키 실루엣 일치), 걷기 중 메시 파손 없음
- **사용자**: 걷기 영상(측면 3루프 + 3/4뷰, `previews/character/user/`) 보고 파일럿 승인. **이 승인이 곧 Phase 2 방향 결정(전부 수제 vs 하이브리드)의 재료다.**

## 7. 완료 기준

1. `run.ps1 all -Profile character`가 Walk 액션으로 클린 통과 (Unity 단언 초록)
2. 비교 시트에서 8키 실루엣이 레퍼런스와 일치 (에이전트 수렴 판정)
3. 발 미끄러짐 기계 검사 통과
4. 부속물 팔로스루가 걷기 영상에서 눈에 보임
5. 더미 프로필 회귀 유지
6. 사용자가 걷기 영상을 보고 파일럿 판정 (성공 → Phase 2 방향 결정으로 이어짐)

## 8. 하지 않는 것 (YAGNI)

Mixamo 연동(파일럿 결과 후 결정) · **멀티 액션 동시 익스포트/NLA 관리** (파일럿은 Walk를 활성 액션으로 단독 익스포트; Idle+Walk 공존은 파일럿 성공 후 첫 후속 작업으로 명시) · run/개성 액션 · Unity 스프링 본 물리 · 텍스처 추출 자동화(별도 정리 항목).

## 9. 리스크

| 리스크 | 완화 |
|---|---|
| 측면 단일 뷰의 깊이 모호성 (어느 다리가 앞인지) | 걷기 사이클의 위상 규칙(교차 보행)으로 해소 가능; 모호 잔존 시 사용자에게 추가 각도 요청 (PLAN §5) |
| AI 시트의 프레임 간 비율 흔들림 | 포즈만 참고, 관절 각도 위주 판독 (PLAN §5 규칙) |
| Rigify IK 컨트롤 사용은 이번이 처음 | 계획 단계 실측 프로브 + 짧은 스파이크 태스크를 계획에 포함 |
| 수제 걷기의 품질 한계 | 그것의 판정 자체가 파일럿의 목적 — 실패도 유효한 결과 |
