# Goblin 게임 캐릭터 리그 — 외부 리뷰용 요약 (2026-09-25 기준)

## 0. 리뷰 요청
Blender에서 만든 게임 캐릭터 리그의 **설계 결정·판정 기준·남은 위험**을 비판적으로 검토해 주세요. 리뷰어는 파일을 볼 수 없으므로 아래 수치와 결정만 근거로 합니다. 질문 목록은 맨 끝(§8)에 있습니다.

## 1. 목표와 범위
- **대상:** Meshy AI가 생성한 "Clay Goblin Warrior" 한 덩어리 메시(91k 정점)와 몽둥이.
  - 키 1.3878 m. 알 모양 몸통, 큰 사각 머리, 가는 팔(튜브 반경 50 mm), 매우 짧은 다리(엉덩이→발목 150 mm).
  - 큰 벙어리장갑형 손(길이 약 310 mm)과 둥근 점토 신발.
- **용도:** Unity(Generic Avatar)용 게임 캐릭터. 애니메이션은 Blender에서 손으로 키를 잡고 FBX로 내보낸다.
- **필요 모션:** 몽둥이 스윙(참조 영상 있음), idle/walk/run, 피격·사망·점프.
- **범위 결정:**
  - 리토폴로지로 새 메시를 만든다.
  - DEF 24본, CTRL/MCH/DEF 3층 구조, 무기 소켓.
  - 얼굴과 손가락 리그는 제외한다.
  - Export용 아마추어는 canonical skeleton JSON에서 생성한다.
- **좌표:** 정면 −Y, 위 +Z, 캐릭터 왼쪽(_l) = +X, 지면 z=0.

## 2. 작업 방식
- **Blender 5.1 headless 스크립트 체인:** 입력 blend → 출력 blend로 이어지고 단계마다 스크립트가 하나씩 있다. 사람의 GUI 작업은 없다.
- **Acceptance Gate G1~G10:** 구현 전에 정의했다. 각 Gate는 독립 checker 스크립트가 raw evidence JSON(입력 파일 sha256 포함)과 렌더를 만든다.
- **판정 주체:** 오케스트레이터(main)만 PASS/FAIL을 판정한다. 시각 품질 항목 [U]는 사용자가 승인한다.
- **에이전트 분리:** 제작 에이전트와 checker 에이전트를 분리했다. 관련 코드가 바뀌면 이전 PASS는 무효가 되고 다시 판정한다.
- **수치 기준 확정:** 대상을 실측한 뒤 확정한다. 이 원칙은 초기에 실측 없이 정한 기준을 여러 번 고친 경험에서 추가했다.

## 3. DEF 뼈대 (G4 PASS)
```
root (non-deform, 지면 원점, 루트 모션)
└ pelvis
  ├ spine_01 → spine_02 → head        (목 없음)
  │            ├ shoulder_x → upperarm_x ┬ upperarm_twist_x
  │            │                         └ lowerarm_x ┬ lowerarm_twist_x
  │            │                                      └ hand_x → weapon_socket_r (R만, non-deform)
  └ thigh_x → calf_x → foot_x          (toe 본 없음)
```
- 24본 중 22본이 deform이다.
- **본 위치:** 최종 리토폴 링 중심을 쓴다(팔꿈치·손목·무릎·발목 링은 측정 피벗과 0.9 mm 이내). 어깨·엉덩이는 측정 피벗을 쓴다.
- **shoulder 본:** 팔 튜브가 필렛 없이 몸통에 바로 꽂혀 있어서 shoulder_root(몸 중심과 접합부의 중간 x) → 접합부로 정의했다.
- **spine_02:** spine_01(벨트 상단)과 head 이음매 높이의 중간에 둔다.
- **Preferred bend:** 원본 팔·다리가 일직선이라 IK 평면이 정의되지 않는다. 그래서 elbow를 +Y로 4 mm, knee를 −Y로 1.5 mm 옮겼다. 굽힘 각은 팔 2.3°, 다리 2.5°다.
- **롤 규약:** 팔·다리 체인은 로컬 X를 공유한다. lowerarm +X 회전은 손을 −Y로, calf +X 회전은 발을 +Y로 보낸다. foot 본은 수평 전방을 향해서 체인 X와 약 16° 차이가 난다.
- **G4 결과:** 44개 기준 PASS(위치 ≤ 2 mm, 롤 평행 ≤ 1°, canonical JSON 재생성 ≤ 1e-5 등).

## 4. 리토폴 (G1·G2·G3 PASS)
- **결과:** GOB_mesh 8,198 tris(body 4,446 + 강체 파트 3,752), 몽둥이 992 tris(16각 회전체, 원점 = 그립, 로컬 +Y = 자루 축).
- **구조:** 변형 몸통은 12각 튜브 + 관절 링이다. 머리·손·신발·벨트는 **정점을 공유하지 않는 별도 강체 셸**이고, 몸통이 그 안으로 들어가 숨는다(설계된 overlap). face INT 속성 `part_id`로 파트를 구분한다.
- **관절 루프:** 팔꿈치에 이름 없는 보조 루프 2개, 무릎에 1개를 추가했다. 어깨 링 구역은 25 mm에서 넓혔다.
- **G2 형상 편차(원본 대비):** 이음매 띠 밖 최대 2.98 mm(기준 3 mm).
  - 사용자 예외: 손목·발목 이음매 띠(축 ±40 mm, 튜브 반경 + 20 mm) 안은 최대 약 7 mm까지 수용했다.
  - 오른손 빈 주먹 구멍(몽둥이를 쥐는 자리)은 유지했다.
- **G3 임시 리그 변형 테스트:** 30°·60°에서 단면 비(굽힌 최소 반경 / rest)를 봤다.
  - 어깨는 0.84~0.97이다.
  - 팔꿈치 60°(0.785)·무릎 60°(0.68~0.74)·엉덩이 60°(0.66~0.74)는 0.8에 못 미쳤다.
  - 루프 배치 변형 6종을 시도했지만 최저점 위치가 루프 수와 무관했다. 선형 스키닝(LBS)·웨이트 원인으로 보고 G5로 넘겼다(사용자 결정).

## 5. 스키닝 (G5 PASS)
- **웨이트:** heat 자동 웨이트에서 시작해 관절별 프로파일로 전환 폭을 정리했다. 정점당 영향 ≤ 4, 합 = 1이다.
- **강체 셸:** 단일 본 100%다(head→head, hand→hand, shoe→foot, **belt→pelvis**; 벨트 높이가 pelvis 본 구간 안에 있다).
- **숨은 몸통 정점:** 셸 안에 숨은 튜브 끝(손목·발목 `_1`~`_end`)은 강체 본을 따라가게 해서 노출을 막았다.
- **twist 본:** Transformation 제약, `SWING_TWIST_Y`, LOCAL/LOCAL이다.
  - upperarm_twist ← upperarm은 −0.5(counter-twist), lowerarm_twist ← hand는 +0.5다.
  - 처음 쓴 Copy Rotation(Euler 추출)은 대각 스윙 90°에서 twist가 15° 새어서 교체했다. 지금 누수는 0.0°다.
- **ROM 84포즈:** 판정 대상 24개, 보고용 60개다. 대표 포즈(스윙 준비/임팩트, walk contact/passing, run 최대 보폭, 피격, 사망, 점프 웅크림)를 포함한다.

| 항목 | 결과 |
|---|---|
| 강체 잔차 | 0.0004 mm |
| 체적 변화 | 최대 2.7% (기준 5%) |
| 30° 단면 비 | ≥ 0.8, 모든 관절 |
| 60° 단면 비 | ≥ 0.75, 실측 후 확정. elbow 0.79, knee 0.77, hip 0.81 |
| 손목 twist 90° | 0.88 |
| 발목 30° | 0.84~0.86 |
| 튜브 끝 노출 | 0 |
| 자기교차 | 모든 교차 쌍을 덮는 최소 면 집합 ≤ 1. 오른쪽 어깨 앞 60°에서 면 1개가 이웃 면 4개를 뚫는 것만 있음 |

- **60° 기준을 0.75로 낮춘 근거:** 무릎 0.77은 2D 모델로 추정한 이 메시의 LBS 한계값(0.770)과 같다. Unity가 LBS라 DQS는 쓸 수 없다. 보정 본을 추가하는 대안은 사용자가 기각했다.
- **사용자가 수용한 극단 각도 한계:** 어깨 들기 130~170°(윗팔만 회전, 어깨뼈 없이), 팔꿈치 140°, 무릎 130°, 손목 꺾기 60°에서 볼륨 손실과 접힘이 있다.

## 6. 조작 리그 (G6.1~G6.9 PASS, G6.10 사용자 GUI 확인 대기)
- **몸통:** CTRL_root > CTRL_torso(COG, pelvis head 위치) > {CTRL_pelvis, CTRL_spine_01 > CTRL_chest}. CTRL_head의 공간은 chest / world다.
  - world는 **회전만 월드에 고정**하고 위치는 chest를 따라간다.
- **팔:** FK(shoulder 공용 / upperarm / lowerarm / hand)와 IK(손 + 팔꿈치 pole, 스트레치 없음)를 `arm_ik_fk`로 섞는다. 기본값은 FK다.
  - 손 IK 공간: world/root/torso. 왼손만 weapon 공간이 추가된다.
- **다리:** FK와 IK를 섞고 기본값은 IK다. knee pole 공간은 foot / world(=CTRL_root)다.
  - foot roll은 MCH 피벗 체인(heel → toe → bank_in → bank_out)으로 만들고 속성 `foot_roll`, `foot_bank`, `heel_twist`, `toe_twist`로 구동한다.
- **무기:** CTRL_weapon의 공간은 hand_r(기본) / hand_l / torso / world다. DEF weapon_socket_r은 계층상 hand_r 자식으로 두고 CTRL_weapon의 월드 transform을 Copy Transforms로 따라간다.
  - **hand_l 공간 대상은 CTRL_hand_fk_l(FK 손)이다.** DEF hand_l을 대상으로 하면 "왼손 IK의 weapon 공간"과 순환이 생긴다. Blender는 influence가 0이어도 제약 관계를 의존성 그래프에 넣는다.
  - 그래서 hand_l 공간은 왼팔 FK일 때만 의미가 있고, 전환 연산자가 조건을 검사해 위반 시 경고와 함께 취소한다.
- **공간 전환 방식:** 월드 행렬 기록 → 속성 변경 → 의존성 갱신 → 월드 행렬 복원(스냅 유지)이다. influence만 바꾸는 방식은 금지했다.
- **연산자 3개:** snap_ikfk, switch_space, reset_rig. blend 내부 텍스트 모듈과 같은 코드의 애드온으로 제공하고, N-패널 UI가 있다.
  - 오토키가 켜져 있으면 키를 넣는다.
  - IK←FK 스냅은 pole 각도를 몇 번 반복 보정한다. Blender pole_angle이 굽힘 평면과 고정 관계가 아니기 때문이다.
- **셰이프·색:** 셰이프는 메시 밖으로 나오게 크기를 맞췄다. 색은 L 파랑 / R 빨강 / C 노랑이다. 기본 가시성은 CTRL만이다.

| G6 항목 | 결과 |
|---|---|
| G6.2 모든 CTRL identity → DEF = rest | 1.5e-5 (기준 1e-4) |
| G6.3 IK↔FK 스냅(체인별 무작위 20포즈, 양방향) | ≤ 1 mm, 1° (자체 점검 최대 0.06 mm / 0.18°) |
| G6.4 공간 전환 전후 | ≤ 0.0001 mm / 0.18° |
| G6.5 튐 없음 | 후보 84개 모두 연속 |
| G6.6 DEF 스케일 | 1 ± 1.5e-5 |
| G6.7 발 planted | 8개 속성 전 범위 통과 |
| G6.8 순환 | 0 (정적 그래프 검사 + Blender 경고 캡처) |
| G6.9 연산자 등록 | 텍스트 모듈 / 애드온 동일 코드 |

### 실측 후 정정한 G6 기준 두 가지
1. **G6.7 발 접지.**
   - 처음 기준은 "신발 최저점 ≥ −1 mm"뿐이었다. 그런데 다리가 거의 곧아서(150 mm, 2.5°) roll/twist 때 IK가 목표에 닿지 못하고 신발이 12~58 mm 뜨는데도 통과했다.
   - 다음 시도에서 피벗 탐색 높이 제한을 두지 않았더니 피벗이 지면 위 64~290 mm로 올라갔다. 그러면 발이 구를 때 접지점이 최대 약 9 cm 미끄러진다.
   - **최종 기준:** 준비 자세(COG −15 mm, 무릎 약 51°)에서 모든 값이 planted여야 한다.
     - IK 도달 오차 ≤ 1 mm
     - 신발 최저점 z ∈ [−1, +3] mm
     - roll·bank는 slip(최저 정점의 수평 이동) ≤ 5 mm
   - 피벗 높이는 0~20 mm로 제한했다.
   - **결과 범위:** roll −29/−33 ~ +26/+29°, bank 최소 ±13°, heel_twist 약 ±35~45°, toe_twist 약 ±15~20°.
   - **발끝 쪽 roll +40° 목표 미달:** 신발 앞코가 위로 휜 저폴리 형상 때문이라 수용했다.
2. **G6.5 튐.**
   - 고정 간격 기준(1 cm / 1°마다 변화 ≤ 간격 × 3 + 1°)이 거의 곧은 관절 근처 IK를 튐으로 오판했다. 실제로는 연속이지만 무릎이 약 35°/mm로 가파르게 변한다.
   - 또 sweep 범위가 다리 길이를 넘어서(발 IK 0.3 m 들기, COG 0.3 m 내리기) 실제 접힘 튐을 만들었다.
   - **최종 기준:** 후보 구간을 4단계(간격/16)까지 이분해, 변화가 원래의 0.5배 이하로 줄면 연속으로 본다.
   - sweep 범위는 치수에 맞게 줄였다: COG 상하 −0.08~+0.01 m, 발 IK 들기 0~0.08 m 등.
   - **한계:** 제곱근형 특이점(완전 펴짐·접힘)은 이 판정으로 못 잡으므로 범위 제한으로 막는다.

## 7. 남은 단계와 알려진 위험
- **남은 단계:**
  - G6.10 사용자 GUI 조작 승인
  - G7 bake: 컨트롤 → DEF 매 프레임 베이크. 무기는 socket offset 애니메이션으로 나간다.
  - G8 FBX export: canonical skeleton에서 생성한 export 아마추어
  - G9 Unity 임포트·비교
  - G10 최종 전 Gate 재검증
- **알려진 위험·한계:**
  1. 기본 자세의 팔·다리가 거의 곧다(2.3~2.5°). 그래서 IK가 rest 근처에서 매우 민감하다: 무릎 약 35°/mm, 팔꿈치는 손 IK 1 cm 이동에 약 12°. 애니메이터가 knee pop을 겪을 수 있다. soft IK는 없고 stretch도 금지했다.
  2. 다리가 150 mm로 극단적으로 짧아 foot roll·twist 가용 범위가 좁다. 발끝 roll은 약 +27°다.
  3. LBS 한계로 60° 이상 굽히면 볼륨이 빠진다: 팔꿈치·무릎 140°/130°에서 접힘이 있다. 보정 본이나 blend shape는 없다.
  4. 어깨 들기 130~170°는 어깨뼈(shoulder 본)를 같이 돌리지 않으면 크게 무너진다. 애니메이션 가이드가 필요하다.
  5. 무기 hand_l 공간은 왼팔 FK에서만 올바르다(순환 회피의 대가).
  6. 발목 입구 링이 rest에서 이미 신발 표면 밖으로 0.25~0.43 mm 나와 있다(리토폴 형상). 포즈에 따라 더 나빠지지 않음만 판정한다.
  7. 체커 G6.8의 Blender 경고 캡처는 알려진 순환으로 검증하지 않았다. 순환 없음의 근거는 정적 그래프 검사(본 부모, 제약 대상, IK 체인, 드라이버 변수)다.
  8. Python으로 커스텀 속성을 쓰면 드라이버가 재평가되지 않는다. 매번 `update_tag()`가 필요하다.
